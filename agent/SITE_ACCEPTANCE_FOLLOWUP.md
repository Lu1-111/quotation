# 「报价」整站验收补修指派

给 agy。本轮处理独立验收发现的首次云授权、生成中刷新、图账错版和旧画像恢复问题。基线为本地 `main@56290b9` 加上次整站交付的工作区改动。独立复跑确认全仓 317 项、十二轮合成回放通过，正式浏览器已能走完输入、证据、改写和撤回。真实知乎公开检索与智谱模型另跑过一轮，有 6 条公开证据进入后端，首段文本约 2.16 秒。下列补测覆盖了当时通过用例的盲区。[上一轮实施方案](SITE_INTEGRATION_PLAN.md) · [上一轮交付回执](DELIVERY_RECEIPT.md)

## 分工与优先级

| 优先级 | 负责线 | 交付 | 放行条件 |
| --- | --- | --- | --- |
| P0 | A · 新版授权 | 首次展示实际拟外发清单，确认后才允许该清单进入云推理。维护 `server.mjs`、材料策略与授权回归 | 未见实际清单、缺少 ID、清单已变化时，合成云模型调用为零 |
| P0 | B · 旧工作台外发边界 | 现有画像及衍生标签走统一授权路径。维护 `web.mjs`、`interaction.mjs` 与工作台 HTTP 回归 | 旧交互能用通用议题，外部检索及模型请求没有未经确认的画像衍生内容 |
| P1 | C · 正式星图恢复 | 刷新恢复正在运行的轮次，图和账单一起更新。维护 `live-session.js`、对应渲染和浏览器测试 | 生成中刷新仍能读流和停止，慢快照或失败时不呈现混合版本 |
| P1 | B · 旧画像任务恢复 | 空快照失败后释放任务，后续可正常重试。保留门禁和取消 | 空快照提示后补入采集记录，同进程刷新成功 |
| P2 | B、C · 边界收口 | 画像超时和取消同时生效，前端空态版本及已采用标识与后端一致 | 增加可控计时和 UI 状态用例 |

A、B、C 可并行。agy 主控负责接口变更与回归合流。同一条测试内使用临时 SQLite、随机回环端口和合成材料。浏览器测试从正式首页进入，使用可控模型阻塞生成或可控快照响应制造确定的时序。

## A · 首次云推理先预览后确认

**复现。** 启用个人材料，首次创建会话被拒，但返回的是空清单。只提交 `cloudConsent: true` 且不带预览 ID 时，当前服务返回 201，首次展示实际片段就标为已确认。随后轮次可把该片段发送给模拟云模型。现有 R-A1 将缺少预览 ID 的创建写成成功用例。[创建门禁](server.mjs#L744) · [隐式确认](server.mjs#L822) · [现有断言](test/p0-a-consent-preview.test.mjs#L301)

**实施。** 保持 `POST /v1/sessions` 两步流程。先校验应用身份和本机只读材料授权，再在本机固定采集快照、规范化并裁剪片段。对非回环推理且拟发送清单有个人片段的情况，首次请求返回 `403 CLOUD_CONSENT_REQUIRED` 和实际清单，`previewConfirmed: false`。客户端显式提交 `cloudConsent: true`、对应的 `outboundPreviewId` 及预览对应的快照标识后，重新核对当前清单与模型目标，匹配时才创建已确认会话。缺 ID、空清单 ID、快照或目标变化均返回当前可确认的清单。预览和确认使用同一规范化口径，入库后的兼容字段以实际确认结果生成。

没有可用个人片段时，按现有空材料分支继续，保留未确认状态。回环模型和明确关闭个人材料的会话继续直接创建。轮次沿用已确认清单边界，涉及新片段时重新预览。保留显式撤回、重启持久化和正在运行时中止的行为。同步更新 [HTTP 契约](HTTP_API_CONTRACT.md) 与 [Schema](schemas/http-api-v1.schema.json)。

**验收 F-A1。** 首次请求返回一份实际非空的未确认清单，模型调用为零。分别验证只传同意、旧的空清单 ID、已变化的片段。三种情况都不能生成已确认会话。用当前匹配清单重试返回 201，首轮模型请求仅包含该清单中的个人片段。

**验收 F-A2。** 用 240 字合成材料分别标记预览前段与裁掉的末段。确认后抓取实际模型输入，逐项比对证据、来源范围和文本，末段标记不出现。撤回后提交省略同意字段的轮次，服务重启后再提交，均拒绝新增云调用。验一次回环模型和一次关闭个人材料的正常路径。

## B · 旧画像外发与任务恢复

**外发边界。** 旧工作台在非回环设置下已能阻止刷新画像，但已有画像的兴趣标签仍会进入旧交互的外部检索和模型提示。保留画像供本机展示与本机逻辑使用。旧交互走外部公开搜索或非回环模型时，使用通用议题及用户主动提供的公开检索内容。需要使用画像衍生词句时，接入已确认清单后才允许外发。授权判断放在构造查询和模型输入前，从各调用点复用。[画像来源](web.mjs#L866) · [旧议题查询及提示词](interaction.mjs#L806)

**验收 F-B1。** 给旧工作台加载一份带独立合成标记的既有画像。在非回环配置及个人材料开关开启时调用 `/api/interaction/topics`，捕获模拟搜索参数与模拟模型输入。二者都不出现画像标记，通用议题照常可用。加一例关闭个人材料，并复跑旧画像启动、同步完成、保存设置、手动刷新四入口门禁。

**任务恢复。** 空快照手动刷新返回 500 后，补入采集记录再刷新也失败。当前同步失败可能在 `runPromise` 初始化前进入 `finally`，导致运行槽未释放。让所有成功、失败和取消路径都释放所属任务槽，较早任务的清理不能覆盖新任务。空快照返回明确的缺数据状态。将调用方取消信号与画像超时信号合并，保留关闭设置时的中止与禁止落库。[画像任务](web.mjs#L464) · [超时处理](profile.mjs#L111)

**验收 F-B2。** 用已获材料授权的回环模型，在同一进程中先对空快照刷新，再补入一条合成记录并刷新。第一次返回可理解的缺数据结果且模型调用为零，第二次成功生成并保存。另测一个延迟上游触发短超时，一个由关闭设置主动终止，均不发生延后落库。

## C · 刷新恢复当前轮次与图账同步

**生成中刷新。** 暂停模型在首段之后，刷新页面。后端快照还有 `activeTurnId` 且轮次为 `running`，页面却恢复成空闲，停止按钮禁用，也不再订阅事件。恢复时从会话快照识别活动轮次，恢复状态与停止按钮，重新订阅同一轮 SSE。整页刷新时可清空当前轮局部文本并从头重放，各事件只应用一次。普通断线继续按 `Last-Event-ID` 补齐。恢复过程只读快照与事件流，不重新提交本轮。快照与订阅之间已进入终态时，处理回放中的实际终态。[恢复状态](../frontend-design/web/src/live-session.js#L229) · [恢复入口](../frontend-design/web/src/live-session.js#L396)

**验收 F-C1。** 从正式首页提交一轮，等首段已显示后刷新，确认仍是同一会话及轮次、可继续显示第二段、可按停止。分别跑成功提交与停止两例，统计页内 POST 次数、SSE 订阅与终态次数。再覆盖刷新前后恰好提交的场景，最终图版本应和服务端一致。

**图账同步。** 补充一条事实使后端从零节点更新到两节点。延迟提交后的快照 GET，页面会先把账单标为 `v1` 并显示 100%，星图仍无节点。收到 `turn.committed` 后先标记「正在同步结果」，以携带该提交版本或更新版本的完整快照为共同渲染来源，一次更新星图、节点列表、账单、事实和改写状态。等待或失败时整组继续显示上一个成功版本，并提供可见的重试入口。忽略过时快照。空态从实际图版本取值，已有改写被采用时只给对应版本加标识。[提交处理](../frontend-design/web/src/live-session.js#L473) · [快照读取](../frontend-design/web/src/live-session.js#L626) · [账单空态](../frontend-design/web/src/analysis.js#L217)

**验收 F-C2。** 在真实浏览器中分别延迟一次提交后快照、令其失败一次。快照未就绪时图和账单均维持旧版本。重试成功后，两者同时更新到新版本，节点、冲突、报价和采用状态均与 API 一致。再撤回全部有效事实，验证空图仍显示真实版本。桌面复跑整条恢复路径，手机尺寸至少复跑输入、空态和重试入口。

## 回执与独立验收

按 `F-A1` 至 `F-C2` 报告测试名、修复前后观测、分支或工作区基线及可复跑命令。保留上一轮全仓回归、十二轮合成回放、正式浏览器闭环、取消、断线与重启验收。启动合成版使用 `cd agent && npm run serve:demo:web`。Codex 将从干净副本重跑新增用例，并在实际浏览器复测生成中刷新与慢快照。
