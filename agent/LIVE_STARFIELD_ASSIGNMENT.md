# 正式星图共用工作台数据实施文档

## 产品入口与数据流

在 `agent/` 配置 `AGENT_BASE_URL`、`AGENT_MODEL`、`AGENT_API_KEY` 和 `ZHIHU_ACCESS_SECRET`，运行 `npm run serve:workbench:starfield`。一套进程启动本机采集 `3005`、AI 工作台 `3210` 和正式星图 `3006`（原 `frontend-design/web/index.html` 封面与三维画布，兼容地址 `18775`）。正式星图使用工作台提供的账号、画像快照、模型配置和知乎搜索配置，自有对局会话与知识星图库。历史公开对话和合成演示分别沿用原有启动命令。

用户先在工作台登录知乎、授权、同步和生成画像，再到「画像」点击「连接正式星图」。`3210` 确认工作台的当前身份和画像快照归属，发放一个五分钟有效的单次配对码。`3006` 兑换配对码后签发 HttpOnly 会话 Cookie。账号切换或撤回授权后会话须重新连接。画像和采集信息在本机只读投影，进入云模型的输入为公开语料和本局交锋材料。

## 观点交锋

1. 开局恰好三条对手观点。前两条来自真实公开检索候选，经本机画像排序确定；第三条从独立的知乎公开检索结果中挑选近期高互动帖。互动量用于选题，不作为结论可信度。题面由 Agent 构造，保持原帖作者与虚构对手的归属分离。
2. 用户选一题后，Agent 拆出对象、前提、范围、机制和结论。首轮对手立论，后续轮先回应用户上一轮实际选的话，再用一个尚可辩护的支点维护原结论。
3. 用户每轮点击一个选项推进。默认三条，每条有不同的切口；第四条须具备独立且已核验的证据。资料不足时给出有区别的检验问题，并记为待查。选项出处可以按需展开。
4. 只有提交成功的十二次点选才计入结算。复用工作台的承重、认知阻力和对手意志机制，移除人为拉开选项分数的校准；证据加成取程序核验结果，意志增减按原公式的 45% 计。意志到零时对手仍会围绕未拆的支点维护原观点，满十二轮统一复盘。
5. 上游故障、取消和重试保留上一轮。SSE 实时显示处理阶段与完整的立论或反驳；客户端从提交快照获取当轮选项。刷新、断线重连和重复点选不能多记轮次。

## 五个 Agent 的职责

| 角色 | 交付 |
| --- | --- |
| 选题与语义 Agent | 从公开帖子生成候选；选题后给出合法依赖图和逐轮焦点 |
| 检索 Agent | 基于公开题意和本轮焦点补查知乎，归一化帖子 ID、作者、片段和链接 |
| 对手 Agent | 首轮立论；后续引用上一轮实际选择的一个片段，再提出本轮反驳 |
| 说服选项 Agent | 交付三到四条可直接说的话及对应证据，核验不足时保留可检验的问题 |
| 复盘与知识 Agent | 十二轮结束后从已选选项中提取带证据的知识，给出归属领域和复盘 |

主控服务负责会话、幂等、证据校验和数值计算。模型只提交候选；程序必须核对引文位于对应片段、主张与原文可对齐、来源属于当前局。模型推理设置由共享模型工厂处理，支持关闭的模型以关闭模式调用。智谱 `glm-5.3-flash` 强制思考，现有 Coding Plan 接口实测 `glm-5.4` 可用关闭参数。若应用要求整条链路关闭，工作台应配置后者或另一经过验证的非思考模型。

## 独立知识星图

知识星图库使用 `knowledge-starfield.sqlite`，学科领域为星系，知识点为可点开的星点。首次绑定用同一工作台画像及其采集快照初始化，以「已接触」展示能溯源的领域和主题。交锋和知识星图是两个板块，星图不参与出题、选项或数值计算。

只有结算提交后，知识导入器才消费已核验的**已选**选项。先匹配已有领域和稳定星点，再创建新领域。附带对局、回合、选项和知乎出处。缺少证据的内容留在复盘的「待查」。对局提交与待入图任务同事务落库，独立知识库按结算 ID 幂等导入。失败时显示「知识待入图」，用户可以重试。

## 验收清单

- 从工作台完成绑定，验证另一个账号不能读本人的会话或知识图。画像换版本时，新局前两题跟随偏好，第三题仍来自独立公开候选。
- 真实知乎和真实模型完整跑十二轮，从同一回合选不同选项，对手下一轮应有可核对的回应差异。检查每轮选项数量、引用真伪以及结算完整性。
- 核对开局、前十一轮和最后一次选择提交前的星图版本。结算后只有已选、已核验的知识入图，支持领域归并、重复交付和中断恢复。
- 交付前执行 Agent、采集服务及前端回归。复测记录需要写明数据模式、模型、实际轮数、可溯源出处和星图差异。
