# 「报价」正式星图真实对话实施指派

给 agy。本轮要把真实知乎搜索、真实模型和正式星图接成一次对话。评委打开首页就能输入一句想说的话，随后只需要和 Agent 交流。Agent 自己检索并阅读知乎公开材料，挑出会影响判断的依据，给出一条可以改的句子。星图随着同一次对话更新，出处放在相应回复旁边，需要核对时再展开。

当前正式页面使用合成会话，真实搜索和真实模型此前在独立接口和工作台里已跑通。新版后端有候选核验入口，默认模型主要在算价后写解释。本轮要接的是**模型先理解这句话和找到的材料，核验后再生成星图与改写**。以本地 `main@56290b9` 及上次交付的工作区改动为基线，保留已通过的授权、续流和图账同版回归。[当前会话入口](../frontend-design/web/src/live-session.js#L531) · [结构化候选入口](turn-orchestrator.mjs#L3963) · [前次交付回执](DELIVERY_RECEIPT.md)

## 评委现场怎样体验

1. **说一句。** 首页放一个可自由输入的框。作者可以输入草稿、想发布的判断，或随手说一句。发送后留在正式星图页面，无需登录、绑定知乎或选择模型。示例只是起手句，点选后仍走本轮的真实链路。
2. **听 Agent 说它看见了什么。** 优先拆一个影响最大的词或条件，再用找到的材料解释。每条关键论断旁至多放必要的出处，点开可看标题、作者、实际使用的摘要片段及原链接。用户可以在原对话里问「你怎么知道？」或「这条其实说的是另一回事」。
3. **把句子说得更准。** 第一轮给出一份可编辑的改写与一句解释，点明保留了什么、收窄了什么。用户可以直接回复自己的版本，或点「试试这句」。下一轮在同一个会话比较同一组证据，显示哪条关系发生了变化。没能确认的部分继续留白。

星图只突出本轮在讨论的主张、证据和关系。回复里的出处与图中的节点互相可定位。第一轮就给出有用的发现或明确的材料边界，后续的追问和纠错让这张图慢慢长出来。公开材料始终保留原作者。它们可支持、反驳或限定一句话，这些关系属于本次讨论，个人立场由本人表达或确认后才成立。公开体验交付关系和改写差异，承重百分比只用于有足够结构的已确认个人图。

### A · 真实公开会话和检索

复用同源宿主与已有 Bearer、Cookie 路径。公开入口使用真实模式及独立存储，由宿主强制 `usePersonalMaterials: false`。浏览器会话只读写自己创建的会话，模型密钥与知乎凭证由服务端持有。拒绝公开客户端送入种子图、工具提议和任意外部接口地址。合成启动命令继续供离线演示和回归使用。

前端从宿主握手获取真实公开或合成模式，再创建相应会话，去掉页面对 `dataMode: "demo"` 的写死。继续复用创建、提交、快照、SSE 与取消的路径。公开搜索沿用官方 Skill，围绕当前主张的论点及适用条件做少量有区分度的查询。保留平台返回的原始链接和原摘要，去重用规范链接或内容 ID。让 Agent 消化搜索结果，用户看到的是本轮选出的依据。缺配置、限额、超时和确实没有可用资料要分别表达。[现有启动与工具装配](serve-cli.mjs#L261) · [搜索结果契约](../information-search/OUTPUT_FORMAT.md) · [HTTP 契约](HTTP_API_CONTRACT.md)

### B · 模型先判断，后端再确认

在正式启动路径注入生产用的 `proposalResolver`，复用已配置的真实模型。模型先把句子拆成主体、动作、条件和可被推翻的范围，拿到本轮有限的公开证据后，提出焦点、关系、证据 ID、建议引用和一份改写。服务端以 Schema 校验结构并核对引用能在原片段找到，主体、场景与谓词能对应。证据只覆盖部分条件时标为「限定」，材料不足时保留未知。两家工厂、两类对象或两种不同做法的结果，不能只凭关键词相同就画成冲突。

用独立的 `publicAnalysis` 保存公开对话里的主张和证据关系。至少交付主张及原文焦点、节点和关系、引用 ID、建议改写及依据、与上一版本的关系变化。公开分析与同一轮次的 `graphVersion` 一起提交，由一次快照更新星图与对话卡片。公开观点图存放在公开分析字段，本人图仍以用户授权及本人确认为入口。新增字段同步项目契约、Schema 和合成样例。

保持真实阶段反馈与可取消。先告诉用户正在核对哪一处，随后流式呈现已核验的解释。关键引文、事实、关系与数值由核验结果渲染。模型输出中的无引号转述、中文数字和百分比也必须与结构化结果一致。输出有疑问时，用当前证据生成简短说明，让用户能继续追问。[候选核验](turn-orchestrator.mjs#L3999) · [现有流式出口](turn-orchestrator.mjs#L4787)

### C · 说话有人情味

保留「报价」的视觉气质。把输入和一条自然的邀请放在首页第一屏。提交后，仍由同一条对话承接提问和改写。证据卡、图和快捷按钮围绕用户正在说的这句话展开。首屏收起「图版本」「总承重分母」「候选关系」等实现词。图里有变化时，用一句具体的话告诉用户哪里变了。

文案要像一个认真听你说话的同伴。先回应你这句话，再问一个值得回答的问题。可以有一点余韵，结论和出处仍说清。以下是语气示例。实际回复中的判断由本轮材料决定。

| 场景 | 可以这样说 |
| --- | --- |
| 首页 | **这句话，你想怎么说？** 把你想写的那句放在这里。我们一起看看，哪里有依据，哪里还想再斟酌一下。 |
| 刚开始 | 我先看看「只会」。如果能找到一个例外，这句话就有再推敲的地方。 |
| 找到有限的依据 | 这位作者说的是批量写稿。它能帮我们看清这一种情况，别的写法还要再找找。 |
| 给出改写 | 原来那层担心可以留着。咱们把话说到那个具体场景里，读者更容易明白你在担心什么。 |
| 图上发生变化 | 加上「反复用同一个提示词」以后，这条反例就不再直接反驳你的句子了。 |
| 资料不足 | 我找到了一些相近的说法，还缺一条能回答你这个问题的证据。这句先留着，我们可以一起把范围说清。 |
| 上游暂不可用 | 这次没能查到资料。你的原句还在这里，等一下可以再试。 |

按钮用「看看这句话」「看看出处」「试试这句」「继续问」。避免长段铺垫、套话、给人打分，以及把每句话都写成隐喻。每轮保留一处新发现、一个解释和一个可继续的动作。现在已有的生成中刷新、取消、断线续读和图账同版机制应覆盖新的公开分析。[现有页面](../frontend-design/web/index.html) · [会话恢复](../frontend-design/web/src/live-session.js#L603)

## 验收与交付

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| L-01 · 一页真实闭环 | 用真实公开模式打开正式首页，临时输入三道来自不同领域的句子，其中至少两道未写入演示语料或测试样例 | 从同页发生真实知乎请求和真实模型调用；能点开至少两题找到的核验出处。记录每题实际召回、所用片段与模型结果。查不到的题能明确显示材料不足 |
| L-02 · 判断有边界 | 使用「甲工厂不允许换班」和「乙工厂可以换班」这类跨主体材料，以及能限定和能直接反驳的正向对照 | 不因词面相似误标冲突；每条已显示边能追溯对应证据；模型提出无源引文、无引号断言或未经核验的数字时，用户可见内容和持久化结果都保持一致 |
| L-03 · 可继续的对话 | 追问一次出处，纠正一个条件，再输入自己的改写 | 同一会话记得当前句子。原句与改写在同批证据下可比；图只变化受影响的关系，未知项有清楚解释 |
| L-04 · 浏览器与降级 | 用桌面和手机尺寸操作。模拟搜索失败、模型失败、生成中刷新和快照延迟 | 用户能取消、继续或重试，原句可找回。图和回复采用同一个已提交版本。缺上游时清楚提示，切换合成演示由用户选择 |
| L-05 · 首次使用 | 找一位没看过开发文档的人，给他首页，让他输入自己的句子并尝试改写 | 能独立找出一条有用的依据，打开出处，完成一次改写。记录他在哪一步犹豫、首个有效反馈及真实检索、模型、整轮耗时。观察实际读懂的内容与界面提示之间的差距 |

自动化用临时库和可控替身，测试真实 HTTP/SSE、结构化核验、拒绝越权字段和旧回归。真实验收从同一可操作页面走，记录脱敏请求 ID、真实上游调用、出处数量、图版本和实际耗时。评委可以现场改题，测试记录不能依赖预写答案。

agy 交付回执须给出可复跑的启动命令、变更基线、L-01 至 L-05 结果和失败项。Codex 会另外选题，从实际浏览器提交，通过真实知乎搜索和真实模型复测，逐条核对可见出处、改写及星图差异。真实个人材料继续以本人授权后的专项验收为准。
